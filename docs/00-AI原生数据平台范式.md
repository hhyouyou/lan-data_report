# 00 · AI 原生数据平台：范式

> 目标不是「BI 加一个聊天框」，而是**以资产为中心、AI 贯穿生产与消费**的数据平台。

---

## 一、先分清三层 AI 价值（价值递增，门槛也递增）

| 层 | 做什么 | 门槛 | 是否构成壁垒 |
|---|---|---|---|
| **L1 交互层** | 问数、解读、自然语言查数据 | 低 | ❌ 半年内所有人都有 |
| **L2 生产层** | 用 AI 开发数据、清洗、建模型、定义指标 | 高（要保证正确） | ✅ 需要工程体系 |
| **L3 资产层** | 把 AI 产出沉淀成可复用的资产（口径、血缘、知识） | 最高 | ✅✅ 真正的护城河 |

市面上绝大多数「AI BI」停在 L1。**你描述的愿景要的是 L2 + L3**，这也是它值得做的原因。

判断标准很简单：如果明天换一个更强的模型，你的产品是变强 20% 还是变强 2 倍？

- 只做 L1 → 变强 20%，别人换模型也一样
- 做了 L2/L3 → 变强 2 倍，因为资产在积累

---

## 二、统一范式：一句话概括整个平台

> **自然语言 → 可校验的声明式资产 → 人工确认 → 版本化生效**

所有角色、所有能力，都是这个范式的不同实例：

| 角色 | 自然语言输入 | AI 产出（资产） | 校验方式 |
|---|---|---|---|
| 数据开发 | 「把这份 CSV 清洗成订单表」 | 清洗管道 DSL | 预览前 100 行 + 规则 diff |
| 数据开发 | 「设计一个交易域模型」 | 表 / 字段 / 关联定义 | Schema diff |
| 数据分析 | 「定义 GMV 口径」 | 指标 YAML | 试算对比历史值 |
| 数据分析 | 「这个看板要加地区 TOP10」 | DashboardPatch | 预览 + 撤销 |
| 所有人 | 「这个数怎么来的」 | 血缘 + 口径 + 知识条目 | 引用到定义与版本 |

**为什么必须是「声明式资产」而不是「AI 直接操作」**：

- 可 diff、可回滚、可测试
- 可人工确认，AI 出错不会污染生产
- 同一份资产可以被人和 AI 共同编辑
- 资产可以跨模型、跨年份复用

> 这条范式是平台的地基。**模型会换，资产不会。**

---

## 三、四类资产 × 三种 AI 动作 = 平台能力矩阵

|  | **生成** | **解释** | **校验** |
|---|---|---|---|
| **数据资产**<br/>表 / 字段 / 血缘 | 建表、清洗管道、模型设计 | 血缘追溯 | 质量规则、分布漂移 |
| **语义资产**<br/>指标 / 维度 / 口径 | 指标定义、同义词、值字典 | 口径问答 | 试算对比、口径冲突检测 |
| **分析资产**<br/>查询 / 看板 | QuerySpec、看板草稿 | 结果解读、异常归因 | 合理性校验 |
| **知识资产**<br/>说明 / 变更 / FAQ | 变更摘要、文档草稿 | 检索式问答 | 冲突/过期检测 |

### 关键：这四类资产有严格的依赖顺序

```
数据资产  →  语义资产  →  分析资产  →  知识资产
（没有表）    （没有指标）    （没有查询）    （没有历史）
```

**所以路线不能反过来**：先做「AI 解读数据」而没有语义层，只能吐出废话；先做「AI 建模型」而没有数据资产，没有校验基线。

一个人只能覆盖 3~4 个格子，选择顺序就按这条依赖链来。

---

## 四、三类用户，同一个底座

| 角色 | 核心诉求 | 入口形态 | 对 AI 的要求 |
|---|---|---|---|
| **数据开发** | 快、可控、可回归 | Agent 工作台（长任务、沙箱、diff） | 生成的东西必须能验证 |
| **数据分析** | 灵活、口径一致 | Copilot（问数 + 指标定义） | 理解业务语境 |
| **数据消费** | 看得懂、拿得快 | 对话入口（问、解读、订阅） | 说人话、可溯源 |

三者共享：**语义层 + 血缘图 + 权限模型 + 知识库**。

如果三类用户各有一套底座，就会变成三个系统——这是很多「AI 数据平台」项目失败的方式。

---

## 五、什么会变，什么不会变

| 会变（每 6~12 个月） | 不会变（3~5 年） |
|---|---|
| 大模型 | 资产 schema（指标/维度/血缘的结构） |
| Prompt | 评测集 |
| Agent 编排框架 | 口径治理流程 |
| 向量库 / RAG 技术 | 权限模型 |
| 前端交互形态 | 数据落地的三层结构 |

**推论：现在最该投资的是「不变的」，不是「会变的」。**

给一个人开发的直接建议：

- ❌ 不要花两周打磨 prompt
- ✅ 花两周把语义模型 schema 和评测集定对
- ❌ 不要追最新的 Agent 框架
- ✅ 把「AI 产出 → diff → 人工确认 → 版本化」这条流水线做出来，换任何模型都能复用

---

## 六、五条工程铁律

1. **AI 永不直连生产库写数据**：沙箱执行 + 人工确认 + 可回滚。
2. **所有 AI 产出都是 diff，不是覆盖**：让人看得见改了什么。
3. **每个能力都要有评测集**：没有评测集 = 无法判断模型升级是变好还是变坏。
4. **解释必须可溯源**：回答「这个数怎么来的」时，引用到具体的定义和版本，而不是模型编。
5. **权限在资产层，不在 prompt**：LLM 不参与权限决策。

## 七、平台成熟度模型

| 级别 | 特征 | 对应能力 |
|---|---|---|
| **L0** | Excel / 手工报表 | — |
| **L1** | 静态看板、固定报表 | 可视化 |
| **L2** | 自然语言问数，数字可信 | 语义层 + 问数 |
| **L3** | AI 参与生产：清洗、建模、定指标，且可控 | 沙箱 + diff + 评测 |
| **L4** | 资产自增长：AI 主动发现口径冲突、推荐指标、维护知识 | 知识层 + 反馈闭环 |

目标 L4，但 **L2 是入场券**。没有 L2 的口径可信度，L3/L4 全是空中楼阁。

---

## 八、一个人怎么走（现实约束）

愿景是 3 年的，执行是 16 周的。两者不冲突，但必须明确「现在在哪个格子里」。

### 按依赖顺序选择格子

| 阶段 | 覆盖的格子 | 为什么是它 |
|---|---|---|
| v0.1~v0.2（已完成） | 语义资产·生成 + 分析资产·生成 | 问数 + 沉淀，L2 入场券 |
| v0.3 | **语义资产·解释/校验**、数据资产·生成 | 口径问答 + Excel 清洗，成本最低、价值最高 |
| v1.0 | 知识资产·生成/解释 | 变更历史 + FAQ，让「解读」有依据 |
| v2 | 数据资产·解释/校验 | 血缘 + 质量规则 |
| v3 | 分析资产·解释 | 异常归因、自动洞察 |

### 一个人做不到的部分要诚实地砍掉

| 不做 | 原因 |
|---|---|
| 通用 ETL 编排引擎 | 大厂做了十年，做不过 |
| AI 自动建模全流程 | 需要大量校验基础设施 |
| 多模态数据（图片/视频）处理 | 与核心价值无关 |
| 通用 Agent 框架 | 直接用一个开源的就够 |

## 九、什么不是「AI 原生」

用来对照，避免自己骗自己：

| 伪 AI 原生 | 为什么不是 |
|---|---|
| 在 BI 上加个聊天框 | 只覆盖 L1，模型一升级优势就没了 |
| 让 LLM 直接写 SQL 执行 | 不可校验、不可复现、危险 |
| 让 AI 无审核地改生产数据 | 数据事故只是时间问题 |
| 把 prompt 当核心资产 | 换模型就归零 |
| 没有评测集 | 无法判断好坏，等于在做玄学 |
| 每个角色一套系统 | 资产不共享，最后变成数据孤岛 |

---

## 十、一句话总结

> **AI 时代的平台竞争力，不在「AI 能做什么」，而在「AI 做出来的东西能不能被信任、被复用、被积累」。**

信任靠校验，复用靠资产，积累靠版本。
这三件事，才是这个平台真正要做的东西。
