# Lan Data Report

> **语义层为地基，问数为主线，看板是问数的沉淀物。**

面向公司内部业务人员的 **AI 原生数据平台**。单人开发，P0 骨架已可运行。

> 平台定位见 [docs/00-AI原生数据平台范式.md](docs/00-AI原生数据平台范式.md)：
> 不是「BI + 聊天框」，而是**以四类资产（数据 / 语义 / 分析 / 知识）为中心、AI 贯穿生产与消费**。
> 统一范式：**自然语言 → 可校验的声明式资产 → 人工确认 → 版本化生效**。

## 快速开始

```bash
# 1. 安装依赖（本机已有 fastapi/pandas 等，可跳过）
python -m pip install -r requirements.txt

# 2.（可选）生成演示电商数据（约 7 万条合成订单，仅用于跑通机制）
python -m server.app.seed

# 3.（可选）加载江苏统计年鉴真实数据
python tools/jsfj_etl.py

# 4. 启动
python -m uvicorn server.app.main:app --host 127.0.0.1 --port 8765

# 5. 打开 http://127.0.0.1:8765
#    顶部右上角会标「真实数据」或「演示数据」，详见 docs/10-数据资产清单.md
```

Windows 也可以直接双击/运行 `./run.ps1`（首次会自动生成演示数据）。

跑测试：

```bash
python -m pytest tests -q
# 53 passed
```

> 不需要配置 LLM 也能跑通全流程：默认走规则引擎。接 LLM 只需要设置
> `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`（OpenAI 兼容接口），看板简介会自动多一步 LLM 润色。

### 实测片段

```text
问：上个月 GMV 最高的 10 个品类
→ bar 图，6 个品类（数据只有 6 类）
  数码 1,822,778 | 男装 1,682,566 | 美妆 1,675,645 …

问：退款率是多少
→ 3.36%
  SQL: SELECT CAST(t.refund_gmv AS REAL) / NULLIF(t.gmv, 0) AS refund_rate FROM (...)

问：华东地区 9 月的新客订单量
→ 127（单行 KPI，地区作为过滤而非分组）

问：退款率是多少 → 点「📖 口径与血缘」
→ 计算口径：{refund_gmv} / {gmv}
  血缘：fact_order.refund_amount / fact_order.paid_amount → refund_rate
  业务含义：退款金额 ÷ GMV，反映成交金额中被退回的比例
  负责人：售后数据组 · 更新于 2026-01-08
  解读：正常区间 2%~5%，超过 8% 需排查商品质量
  影响面：refund_rate 被 0 个指标依赖

看板点「提交审批」
→ 自动跑 Lint：命名 / 分层 / 图表类型 / 布局重叠
→ 有 error 直接拒绝，并列出违规项
→ submitted → approved → published
→ 只有 published 能生成分享链接

从模板生成看板（结构化入口，与 AI 共用同一个网关）
POST /api/templates/business_review/create-dashboard
→ 6 张卡片全部落库并取到数：KPI 3 张、趋势 29 行、品类 6 行、渠道 5 行

导入一份中文表头的 Excel
→ 订单日期→order_date、销售区域→region、订单金额→amt_order、是否新客→is_new_user
→ 自动识别类型：time / number / boolean
→ 生成语义草稿：2 指标 / 4 维度，Lint 通过
→ 保存并激活
→ 问：8月各渠道的订单金额
   直播 20,100.5 | 推荐 15,200 | 搜索 14,800 | 广告 4,100

「开发」页对话式建模
  用户> 加一个客单价指标，等于订单金额/订单数量
  AI  > 已新增派生指标 m1（客单价），表达式 {amt_order}/{cnt_order}
  用户> 把订单金额改名为成交金额
  AI  > 已改名（原名称保留为同义词）
  用户> 检查一下
  AI  > ✓ 结构校验与规范校验都通过，可以保存
  → 保存并激活 → 问「9月各渠道的成交金额」→ 直播 39,000.5 / 推荐 15,200 …

「看板」页点「从模板创建」
  选「经营分析看板」+ 填标题
  → 自动生成 6 张卡片：3 张指标卡 + GMV 趋势 + 品类对比 + 渠道对比
  → 草稿状态 → 提交审批 → 通过 → 发布 → 分享链接

切换模型到「江苏统计年鉴」（右上角模型切换 / 或 API activate）
  问：2020年江苏GDP            → 104,566.56 亿元
  问：江苏GDP趋势              → 56 个年份折线（1952–2024）
  问：江苏人口近十年            → 2017–2024 年度趋势（自动识别跨年）
  问：城乡收入比                → 2.04（2024，派生指标 城镇/农村）
  问：2024年各市GDP            → 13 行，苏州 26,726.98 亿居首
  问：苏南GDP                  → 77,844.68 亿（与年鉴三大区域表一致）
  问：各市人均GDP排名           → 无锡 216,699 元第一
  问：苏南和苏北的城镇化率       → 83.3% / 67.0%（按人口加权）
  看板：从「江苏统计年鉴看板」模板创建 → 10 张卡片全部取到数
```

## 架构一句话

```
自然语言 ──┐
           ├─▶ QuerySpec ─▶ 统一查询网关 ─▶ SQL ─▶ 结果 ─▶ 图表/看板
看板卡片 ──┘        （同一份契约、同一个编译器、同一套权限）
```

**AI 与看板共用一条查询管线**，所以两边的数字永远一致——这是这类产品最容易翻车的地方。

## 接下来

1. 把 `semantic/ecommerce.yaml` 换成你们真实业务域的表和指标
2. 用 `tools/check_semantic.py` 校验
3. 写第一个真实数据的导入脚本（Excel 或业务库）
4. 跑一遍用户真实问题，看规则引擎命中率——**这个数字决定要不要马上接 LLM**
